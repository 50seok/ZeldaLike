## 1. 개요

**한 줄 피치**: 젤다의 화학엔진(야생의 숨결)을 2D 탑다운 젤다(지혜의 투영) 형태에 이식한 퍼즐 액션 어드벤처 미니게임.

**벤치마크 (역할 분담)**
| 벤치마크 | 가져오는 것 |
|---|---|
| 야생의 숨결 (BOTW) | **아키텍처**: 화학엔진(재질 태그+상태+반응표), 데이터 주도 설계 |
| 지혜의 투영 (2024) | **게임 형태**: 2D 탑다운, 방 단위 던전+카메라 전환, 자물쇠-열쇠 구조, "시스템으로 퍼즐을 푸는" 문법, 아기자기한 연출 |

**목적**
- **학습**: BOTW가 GDC에서 공개한 "데이터 주도(data-driven) 화학엔진" 아키텍처를 직접 구현하며 게임 아키텍처 설계를 체득한다.
- **포트폴리오**: itch.io에 공개해 "기획→구현→배포 완주" 이력을 만든다.

**핵심 가설**: 반응 로직을 하드코딩하지 않고 태그+규칙표 데이터로 분리하면, 콘텐츠(오브젝트·무기·퍼즐) 추가 비용이 극적으로 낮아진다 — BOTW가 증명한 방식이 1인 규모에서도 유효한지 검증한다.

## 2. 핵심 컨셉 — Chemistry Engine

BOTW 분석(GDC 강연·zeldaret 디컴파일)에서 도출한 설계 원칙을 요구사항으로 명문화한다.

### 2.1 설계 원칙 (아키텍처 요구사항)
1. **모든 오브젝트는 데이터로 정의된다**: 재질 태그 + 현재 상태를 데이터(Godot 커스텀 Resource, `.tres`)로 가진다. BOTW의 GParamList에 대응. **무기·방패도 예외 없이 같은 시스템의 오브젝트다** (나무 칼은 불에 타고, 금속 방패는 전기가 통한다 — BOTW 그대로).
2. **반응은 규칙표 조회로 결정된다**: `if (무기 == 나무칼 && 접촉 == 횃불)` 같은 하드코딩 금지. (재질, 상태) × (재질, 상태) → 결과를 정의한 **반응 규칙표 리소스** 하나를 엔진이 조회한다.
3. **콘텐츠 추가 = 데이터 추가**: 새 오브젝트·무기는 씬 + 재질 태그 리소스만 만들면 기존 모든 반응이 자동 성립한다. 엔진 코드 수정 0줄.
4. **드랍도 데이터다**: 파괴 가능한 오브젝트·몬스터의 액터 리소스에 **드랍 테이블 필드**를 둔다(BOTW GParamList의 DropTable 대응). 드랍 확률·품목 변경도 코드 수정 없이 데이터만 고친다. 상세는 §3.3.

### 2.2 재질 태그 (Material)
| 태그 | 예시 오브젝트 |
|---|---|
| WOOD (나무) | 상자, 나무문, 통나무, **나무 칼·나무 방패** |
| METAL (금속) | 철창, 금속 상자, 스위치, **금속 칼·금속 방패** |
| GRASS (풀) | 수풀, 덩굴 |
| CLOTH (천) | 커튼, 깃발 |
| WATER (물) | 웅덩이, 물줄기 |
| ICE (얼음) | 얼음 블록 |

### 2.3 상태 (State)
| 상태 | 의미 |
|---|---|
| BURNING (불붙음) | 접촉한 가연물에 전파, 일정 시간 후 소멸(재) |
| WET (젖음) | 불 면역, 전기 전도 |
| CHARGED (전도) | 접촉한 금속·젖은 것에 전기 전파 |
| FROZEN (얼음) | 이동 불가, 불에 해빙 |

### 2.4 필수 반응 최소셋 (MVP 반응표)
| 입력 | 결과 |
|---|---|
| 불 + 나무/풀/천 | 연소 → 전파 → 소멸(재). **장비 중인 나무 무기·방패도 대상** |
| 불 + 풀 + 바람 | 바람 방향으로 연소 전파 |
| 물 + 불붙음 | 소화 (BURNING 해제, WET 부여) |
| 전기 + 금속 | 전도 (인접 금속으로 전파). **금속 장비 착용자에게도 전달** |
| 전기 + 젖음 | 감전 (WET 오브젝트·캐릭터에 피해) |
| 불 + 얼음 | 해빙 (FROZEN 해제, WATER 생성) |

> 바람: 전역 벡터 1개(방 단위)로 단순화. BOTW의 필드 시뮬레이션을 흉내내되 규모는 최소로.

## 3. 게임플레이

**코어 루프**: 마을에서 스토리·힌트 수집 → 던전 방 진입 → 전투 + 화학 반응으로 퍼즐 해결 → 열쇠 획득·문 개방 → 보스 격파 → 엔딩.

### 3.1 플레이어 액션
- 이동 (8방향, 2D 탑다운) — 키보드 기본, 게임패드 지원(Godot InputMap이라 추가 비용 거의 0)
- **칼**: 근접 공격 (나무 칼→불에 취약 / 금속 칼→전기 전도, 화학엔진 적용 대상)
- **활**: 원거리 공격 — 일반 화살 + 속성 화살(불/전기)
- **방패**: 방어 (나무/금속 재질별로 화학 반응 다름)
- 집기 / 던지기: 오브젝트 운반 (화학 반응의 "배달" 수단)
- 물 항아리: WET 상태 부여 도구
- 일시정지 메뉴 (재개/타이틀로)

### 3.2 카메라·연출 (2D 젤다 문법 — 지혜의 투영 기준)
- **방 전환 카메라**: 방 경계에서 화면이 밀려 넘어가는 스크롤 전환 (Godot Camera2D limit + 트윈)
- **아이템 획득 연출**: 주요 아이템(활·열쇠·하트조각) 획득 시 치켜들기 + 팡파레 + 텍스트 ("활을 얻었다!")
- 퍼즐 해결 시 "짜란" 징글 + 문 열림 연출

### 3.3 아이템 & 드랍 시스템

#### MVP 아이템 목록 (이게 전부 — 추가 금지)
| 분류 | 아이템 | 획득 경로 |
|---|---|---|
| 장비 | 나무 칼(시작), 금속 칼, 나무 방패(시작), 금속 방패, 활, 물 항아리 | NPC 지급(대장장이) / 던전 보물상자 (획득 연출) |
| 소모 | 하트(즉시 회복), 화살 | 필드 드랍 (아래 드랍 테이블) |
| 진행 | 작은 열쇠, 보스 열쇠 | 퍼즐 해결 보상 / 특정 몬스터 드랍 (획득 연출) |
| 수집 | 하트조각 | 퍼즐·비밀 방 보상 (획득 연출) |

#### 드랍 규칙 — 화학엔진과 동일한 데이터 주도
- 파괴 가능한 액터(수풀·항아리·몬스터)는 리소스에 **드랍 테이블**(.tres)을 가진다: `[{아이템, 확률}, …]`
- **상태 조건부 드랍**: 파괴 시점의 상태(State)에 따라 다른 테이블을 참조한다 — BOTW의 "불로 잡은 동물은 구운 고기" 방식. MVP는 조건 축을 **기본 / BURNING 2개로 제한**(폭발 방지)
- 예시:

| 액터 | 기본 파괴 (칼로 베기) | BURNING 상태로 파괴 |
|---|---|---|
| 수풀 | 하트 20% / 화살 20% | 드랍 없음 (재만 남음 — 태우면 편하지만 보상 포기) |
| 항아리 | 하트 30% / 화살 30% | — (불연 재질) |
| 우드가드 (§4.1) | 화살 50% | 하트 50% (불로 잡으면 다른 보상) |
| 아이언셸 (§4.1) | 작은 열쇠 (고정, 던전 설계상 배치) | 동일 |

- **픽업 방식**: 필드 드랍은 접촉 즉시 획득(젤다 관례). 장비·열쇠·하트조각은 획득 연출(§3.2)과 세트
- **MVP 단순화**: 바닥에 떨어진 픽업 아이템 자체는 화학 반응 대상이 아니다(즉시 획득형이라 상호작용할 틈이 없음). 화학 대상은 "운반 오브젝트"만 — 이 경계를 넘는 설계(예: 떨어진 화살에 불이 붙음)는 Post-MVP

#### 성장·자원 (RPG 요소)
- **하트 시스템**: 시작 하트 3개, 하트조각으로 최대 5~6개까지 확장
- **인벤토리**: **데이터 모델은 처음부터 확장형**(아이템 ID 리스트 + 수량 — 그리드 UI를 나중에 얹을 수 있는 구조). MVP UI는 핫바(도구 전환) + 카운터(열쇠·화살·하트조각)만
- **장비 교체 = 성장**: 나무 칼→금속 칼 교체가 성장 곡선 역할(강화 시스템 없음). 단 금속 장비는 전기에 취약해지는 트레이드오프(§2.4) — 화학엔진이 밸런스 장치를 겸함

### 3.4 세이브 & 스토리 진행
- **세이브/로드**: 방 클리어 시 자동 저장 1슬롯 (JSON, `user://`) — 타이틀에서 "이어하기"
- **스토리 플래그**: 진행 상태를 bool 플래그로 관리(세이브에 포함) — "촌장과 대화함 → 던전 문 개방", "정령 구출 → 보스 방 개방" 같은 게이트를 구동
- **NPC 대화**: 대화박스(타자 효과). 분기 없음(선형). NPC는 두 층위 —
  - **기능 NPC 3명** (촌장·대장장이·학자): 힌트 + 스토리 진행 게이트
  - **주민 NPC 3~4명** (플레이버): 각 1~2줄 대사로 마을 생활감 담당. **스토리 플래그에 따라 대사 1회 교체**(폭주 걱정 → 정령 구출 후 희망) — 대화 시스템·플래그 재사용이라 추가 비용은 대사 작성뿐
  - **닭 1~2마리**: 대화 없음, 도망 FSM만. **화학 태그 보유**(깃털=가연) — 불붙으면 뛰어다니며 불을 옮기는 창발 이스터에그(화학엔진이 아군/적/동물을 구분하지 않음을 전시)
- **스토리 연출**: 오프닝/엔딩 = 정지 일러스트 + 텍스트 (확정). 인게임 스토리는 대화박스와 석판으로

### 3.5 스토리 구성안 (3막, **확정** — 2026-08-25 채택)
> 등장인물·장소 이름은 가칭(구현 중 개명 가능하되 구조는 이 절이 기준).

- **배경**: 불·물·전기·얼음 네 원소의 조화로 유지되던 마을 "옹달마을". 마을 지하 유적의 봉인이 풀리며 원소가 폭주 — 우물은 얼고, 밭은 불타고, 대장간엔 번개가 친다.
- **1막 — 마을과 여정**: 오프닝 일러스트(원소 폭주). 주인공은 견습 연금술사. **촌장**이 사명을 주고 마을 밖 길을 열어줌(플래그①). **대장장이**가 금속 칼·방패 제공 + 전기 힌트. **학자**가 화학 반응 힌트 담당. 유적까지는 초원→숲→폐허 세 필드를 지나는 여정(§4.2) — 폭주가 심해지는 순서로 배치되어 유적이 진원지임을 암시.
- **2막 — 유적 (던전)**: 방마다 폭주한 원소를 화학 반응으로 진정시키며 진행. 중간에 갇힌 **원소 정령**을 구출(플래그②)하면 정령이 보스의 약점(젖으면 감전에 취약)을 알려주고 보스 방이 열림. 석판 3~4개로 유적의 내력(과거 연금술사들이 원소를 봉인한 이유)을 조각조각 전달.
- **3막 — 보스·엔딩**: 보스는 폭주 원소가 뒤섞여 태어난 "혼돈의 코어". 정령의 힌트대로 화학으로 스턴 → 무기로 공격. 격파 시 원소 균형 회복 → 엔딩 일러스트(마을 복구, 주인공은 정식 연금술사로).
- **전달 수단 정리**: 오프닝/엔딩 일러스트 2장 + 기능 NPC 3명 + 주민 NPC 3~4명(각 1~2줄×2벌) + 석판 3~4개 + 정령 대화 1회. 이게 전부 (컷씬 없음).
- **환경 연출(마을)**: 언 우물·불탄 밭·번개 치는 대장간 = 오프닝 일러스트의 원소 폭주를 마을 타일로 재확인 — 대사 없이 세계관 전달(타일 배치만이라 비용 최소).

### 3.6 승리/패배
- **승리**: 보스 격파 → 엔딩. 보스는 **화학 상호작용으로 약점 노출(물 뿌려 적신 후 감전 스턴) → 스턴 중 칼/활로 공격**하는 정통 젤다 3페이즈 패턴
- **패배**: 하트 0 → 마지막 저장 지점에서 리스폰

## 4. 콘텐츠 스코프 (MVP)

### 포함
- **월드**: 옹달마을(허브) + **필드 3개** + 던전 1개 — 상세는 §4.2
- **던전 방 5~7개** — **자물쇠-열쇠 구조**(작은 열쇠 1~2개 + 보스 열쇠 1개, 잠긴 문으로 진행 순서 제어. 2D 젤다 던전 문법)
- **화학 퍼즐 3~5개**: 각 퍼즐은 서로 다른 반응 조합을 강제한다 (예: ① 덩굴 태워 길 뚫기 ② 물 뿌려 전기 회로 연결 ③ 얼음 녹여 스위치 누르기)
- **비밀 장소 2개**: 폭탄 대신 **화학으로 발견** — 던전 비밀 방 1(마른 덩굴 태우면 노출) + 숲 필드 비밀 통로 1(§4.2). 보상 = 하트조각
- **보물상자 2~3개**: 장비(금속 칼·방패, 활)와 하트조각의 획득 지점 (§3.3 아이템 목록과 대응)
- **적 4종 + 보스 1**: 상세 설계는 §4.1 · 리젠 규칙은 §4.2
- **타이틀(새 게임/이어하기) + 엔딩 화면**, 일시정지 메뉴
- 플레이 분량 목표: 40~60분

### 4.1 몬스터 설계

**설계 원칙**: 몬스터도 재질 태그를 가진 화학 오브젝트다(§2.1). 4종은 각각 **화학엔진의 다른 축을 검증하는 역할**을 하나씩 맡는다 — 같은 축을 검증하는 중복 몬스터는 만들지 않는다.

| 몬스터 (가칭) | 재질 | HP | 행동 패턴 | 화학 상호작용 (검증 축) | 드랍 | 등장 |
|---|---|---|---|---|---|---|
| **덩굴이** (기본몹) | GRASS | 하트 1 | 플레이어 발견 시 직선 돌진, 접촉 피해 ½ | **불에 즉시 연소 사망** — "불 = 풀 삭제" 축. 칼 2방으로도 처치 가능 (화학은 지름길이지 필수 아님) | 하트 20% / 화살 20% | **초원 다수·숲 소수(리젠 파밍원)**, 던전 초반 2~3마리 무리 |
| **우드가드** (방패몹) | WOOD(방패)+일반(몸) | 하트 2 | 플레이어를 향해 정면 유지, 전진, 정면 공격 반사 | **불화살로 방패 연소 제거** → 무방비. 또는 뒤로 돌아 베기 — "장비도 화학 대상" 축을 적에게 적용 | 화살 50% / BURNING 처치 시 하트 50% | 숲 필드, 던전 중반 |
| **엠버** (원거리몹) | 없음(불꽃체) | 하트 1 | 거리 유지하며 불덩이 투사(맞으면 ½ + 대상에 BURNING 부여) | **플레이어의 나무 장비에 불을 붙이는 유일한 적** — "내 장비가 탄다"를 체감시키는 장치. **물 항아리 적중 시 즉사** ("물 = 불 소화" 축) | 하트 30% | 숲·폐허 필드, 던전 중반 — 우드가드와 조합 배치(불덩이가 우드가드 방패에도 붙음 — 아군 오사 유도 가능) |
| **아이언셸** (중장몹) | METAL | 하트 3 | 느리게 접근, 정면 칼 공격 무효(튕김), 접촉 피해 1 | **물 뿌려 WET → 전기 화살 감전 → 스턴 3초 중에만 피해 가능** — "전기+젖음=감전" 축. **보스전 콤보의 예행연습** | 던전 개체=작은 열쇠(고정) / 폐허 개체=화살 5 | **폐허 필드 1마리(연습용, 열쇠 없음)** + 던전 후반 1마리(열쇠) |

**보스 — 혼돈의 코어** (하트 표시 없음, 스턴 3회로 격파)
- **격파 루프**: 물 뿌려 WET 부여 → 전기 화살로 감전 스턴 → 스턴 중 칼로 코어 타격 (×3회). 아이언셸에서 학습한 콤보의 확장 — 정령이 힌트 제공(§3.5)
- **페이즈 1**: 불덩이 탄막 (엠버 패턴 확장). 바닥 수풀에 불이 번져 지형이 좁아짐
- **페이즈 2** (1타격 후): 바닥 일부를 FROZEN으로 얼림(이동 제한) + 덩굴이 2마리 소환 — 얼음은 보스의 불덩이로도 녹음(화학이 보스 패턴끼리 상호작용)
- **페이즈 3** (2타격 후): 이동 속도 상승, 탄막 밀도 증가. 페이즈 추가 기믹 없음(밸런싱 수렁 방지)
- 보스 방 고정 배치: 물 웅덩이 2곳(항아리 리필), 화살 항아리 2개 (자원 고갈로 인한 막힘 방지)

**공통 규칙**
- **AI는 단순 FSM 코드로 구현** (대기→추적→공격 3상태). 화학 반응·드랍과 달리 AI는 데이터 주도 대상이 아님 — BOTW식 노드그래프(.baiprog 대응)는 비스코프(§4)
- **감전 스턴**: CHARGED 접촉 시 모든 몬스터 공통 2초 경직 (아이언셸만 3초 + 유일한 피해 기회)
- **리스폰**: 방 재진입 시 리스폰. 단 **열쇠 드랍 몹(아이언셸)은 처치 플래그를 세이브에 저장**해 리스폰 제외 (열쇠 중복 방지)
- 몬스터 수치(HP·피해·확률)는 전부 액터 리소스(.tres)에 — 밸런싱은 M5에서 데이터만 수정

### 4.2 월드 구조 & 몬스터 리젠

#### 월드 구조 (오버월드감)
- **연결**: 옹달마을(안전지대) ↔ ① 초원 필드 ↔ ② 숲 필드 ↔ ③ 폐허 필드 → 던전(방 5~7개)
- **옹달마을 구성**: 기능 NPC 3 + 주민 3~4 + 닭 1~2(§3.4), 집 4~5채·언 우물·불탄 밭(환경 연출 §3.5), 몬스터·리젠 없음
- **지름길 게이트**: 폐허 ↔ 마을 직결 통로 — 폐허 쪽에서만 열 수 있는 한 방향 게이트(젤다 관례의 루프 개방). 개방 후엔 보스 재도전·파밍 왕복이 짧아짐
- **카메라 이원화**: 필드 = 스크롤 맵(Camera2D 추적 + limit, **방 4~6개 크기 상한**) / 던전 = 방 전환 카메라(§3.2) 유지

| 필드 | 테마 | 주요 몬스터 | 화학 전시 요소 |
|---|---|---|---|
| ① 초원 | 튜토리얼·파밍 | 덩굴이 무리 | 수풀 다수(베기/태우기 드랍 차이 체험), **바람 부는 지역**(불 전파 시연) |
| ② 숲 | 조합 전투 | 우드가드+엠버 혼성 | 엠버 불덩이→우드가드 방패 오사 연출, **마른 덩굴 비밀 통로 1**(하트조각), 물 웅덩이 |
| ③ 폐허 | 던전 전 관문 | 아이언셸 1(연습용)+엠버 | **물+전기 콤보 예행연습**(던전보다 먼저 안전하게 학습), 지름길 게이트 |

#### 몬스터 리젠 시스템 (혼합형)
- **스폰포인트 = 데이터**: 필드 씬에 SpawnPoint 노드 배치, 파라미터는 .tres — `몬스터 종류 / max_alive / respawn_sec / 활성 조건 플래그`. 화학·드랍과 같은 데이터 주도 원칙(§2.1-4)
- **필드 (시간 기반)**: 처치 후 `respawn_sec`(기본 45초) 경과 + **스폰포인트가 화면 밖일 때만** 재등장(눈앞 팝인 금지). 필드당 동시 마릿수 상한: 초원 5 / 숲 5 / 폐허 3
- **던전 (재진입 기반)**: 방 재진입 시 리스폰, 열쇠몹(던전 아이언셸)만 처치 플래그로 제외 (§4.1 공통 규칙)
- **마을**: 몬스터·리젠 없음 (안전지대)
- **파밍 루프**: 초원의 덩굴이+수풀 리젠 = 하트/화살 상시 수급처. 보스 도전 전 자원 보충 동선이 성립(보스 방 고정 배치 §4.1과 상호 보완 — 방 안은 최소 안전망, 부족하면 필드 파밍)
- 리젠 수치(respawn_sec·마릿수 상한)도 전부 데이터 — 밸런싱은 M5에서 수정

> **컷 라인**: 일정 위험 시 ③ 폐허 필드를 컷하고 숲→던전 직결로 변경(지름길 게이트도 함께 컷). 폐허의 역할(콤보 예행연습)은 던전 아이언셸 방 앞에 물 웅덩이를 추가하는 것으로 최소 대체. 이 컷으로 열쇠 동선은 깨지지 않음(열쇠는 던전 개체 소관).

### 비스코프 (만들지 않는다 — 사유 명시)
| 제외 | 사유 |
|---|---|
| 오픈월드 | 1인 규모에서 콘텐츠 밀도 확보 불가 (합의됨) |
| 애니메이션 컷씬 | 정지 일러스트+텍스트로 대체 (확정) |
| 화폐·상점 경제 | 경제 밸런싱은 별개 프로젝트급 — 드랍(하트/화살)으로 충분 |

| 그리드형 풀 인벤토리 **UI** | MVP는 핫바. 단 **데이터 모델은 확장형으로 먼저 설계** → Post-MVP에서 UI만 추가 (§9) |
| 대화 분기·퀘스트 시스템 | 선형 진행에 불필요. 스토리 플래그(bool)로 충분 |
| BOTW식 AI 노드그래프 | 몬스터 4종 규모엔 과잉 — 단순 FSM 코드로 충분 (§4.1). 데이터 주도는 화학·드랍까지만 |
| 던전 맵 화면(지도+나침반) | 방 5~7개 규모에선 불필요 → Post-MVP (§9) |
| 모바일 지원 | 터치 UI 별도 설계 필요 |

> M1~M2만 끝나도 "화학엔진 + 전투 데모"로 성립하게 설계한다 (리스크 §7 대응).

## 8. 성공 기준

1. **플레이 검증**: itch.io 링크를 받은 사람이 튜토리얼 없이 첫 화학 퍼즐을 풀 수 있다.
2. **아키텍처 검증**: 새 오브젝트 1개(예: "가죽 방패")를 **엔진 코드 수정 0줄**, 데이터 파일 추가만으로 게임에 넣고 기존 반응이 전부 동작한다. **드랍 테이블 변경(확률·품목·상태 조건)도 데이터 수정만으로 반영된다.**
3. **완주 검증**: 타이틀 → 엔딩까지 60분 내 클리어 가능하고, 중간에 껐다 켜도 이어하기로 복귀된다.
4. **젤다 문법 검증**: 방 전환 카메라·자물쇠-열쇠 던전·획득 연출이 있어 "2D 젤다라이크"로 인식된다.

## 9. Post-MVP 로드맵 (MVP 완주 후에만 착수)

우선순위 순. MVP 데이터 모델이 이미 지원하도록 설계해 두는 항목은 ★ 표시.

1. ★ **그리드형 풀 인벤토리 UI** — 아이템 모델은 MVP부터 확장형이므로 UI 작업만
2. **던전 맵 + 오버월드 맵 화면** (지도+나침반 아이템 — 필드 3개 체제라 가치 상승했지만 여전히 MVP 제외)
3. **던전 2** — 새 재질·상태 태그 1~2종 추가와 세트 (아키텍처 검증 2차)
4. ★ **에코 스타일 소환 요소** (지혜의 투영 벤치마크 심화) — 화학 오브젝트를 "복제 배치"하는 능력. 데이터 주도 설계면 오브젝트 소환은 씬 인스턴스화로 저비용
5. 모바일(터치 UI) / 한국어+영어 2개 언어
